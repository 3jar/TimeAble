# TimeAble 기획서 — 시간표 입력·데이터 연동 (레퍼런스)

> 2026-11-11 · 발표용 초안. **API/연동 파트 원작자가 참고할 레퍼런스** 수준으로 정리.
> 기획안의 미결 항목(시간표 입력 방식, 포털 연동 보안)을 GLS 연동으로 해소한 내용.

## 요구사항 — 시간표 입력

**핵심 (2주차 끝까지)**
- 성균관대 **GLS(킹고) 로그인 → 본인 시간표 자동 가져오기(import)** → 복셀 지형의 입력 데이터(`busy` 격자)로 변환
- 기획안의 "OCR/붙여넣기" 대신 **포털 자동 연동**으로 확정 (더 정확·빠름)

**부가 (시간 남으면)**
- **공개 강의계획서 조회**(무로그인) — 과목 상세/주차계획 보강
- **Canvas(i-Campus) 과제·마감일** 연동 — 바쁜 시간 보강

**이번에는 안 함**
- 타 대학 지원, GLS 세션 상시 유지, 실시간 시간표 동기화

## 흐름 · API

**프로그램 흐름 (시간표가 들어오는 길)**
```
킹고 로그인(필요시 이메일 OTP 1회) → 시간표 import 1회
   → 요일·교시 파싱 → busy 격자(30분×요일) → Supabase 저장(members.busy)
   → 이후엔 캐시로 즉석 조회 (매번 재로그인/재계산 없음)
```

**사용할 API와 키 필요 여부**

| 소스 | 용도 | 키/인증 |
|---|---|---|
| **GLS(kingoinfo) `.do`** | 본인 시간표(요일·교시) | 학교 SSO 로그인 필요 (별도 API키 없음) |
| GLS 공개(`E_`) 엔드포인트 | 강의계획서 | **무로그인**(공개) |
| Canvas(i-Campus) API | 과제·마감(부가) | 개인 토큰 |
| Supabase | 데이터 저장/인증 | 프로젝트 키(env) |

## 기술적 제약조건 — 파일 구성

Python · uv. 시간표 연동은 `src/timeable/gls/` 패키지:

| 파일 | 담당 기능 |
|---|---|
| `gls/http.py` | 킹고 SSO 로그인 + GLS 시간표 조회(`timetable`) |
| `gls/syllabus.py` | 공개 강의계획서 조회(무로그인) |
| `gls/parse.py` | 교시 문자열 → `Meeting(요일·시작·끝)` |
| `gls/grid.py` | `Meeting` → `busy[요일][칸]` 격자 → availability 입력 |
| `availability.py` | (기존) 개수기반 지형 계산 |

## 보안 설계 (기획안 "포털 연동 보안" 우려 해소)

기획안 주의사항: *"학번·비밀번호를 서버로 받는 구조는 보안·약관 문제."* → **해법:**
- **일회성 import 모델**: 로그인→격자 추출→저장 후 **세션·비밀번호 즉시 폐기**
- 서버에 남는 건 `busy` 격자(민감정보 아님)뿐 — **비번·세션 at-rest 0**
- 전 구간 HTTPS, 비번은 저장·로그 금지
- (상세 설계: `docs/superpowers/specs/2026-11-11-gls-web-login.md`)

## 이러면 다 된 것 (확인 가능한 문장)

- 사용자가 킹고로 로그인하면 **본인 실제 시간표가 자동으로 격자화**되어 그룹 지형에 반영된다.
- 로그인 후 **빈 시간 블록이 수업 종료 시각과 정확히 일치**한다. *(실제 7과목으로 검증 완료)*
